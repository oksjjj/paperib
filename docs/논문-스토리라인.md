# 이동통신 로밍 데이터 기반 TSAD — 논문 스토리라인

초안 스토리·평가 지표·주장 범위를 한곳에 정리한다.  
**목차:** [논문-목차-스토리라인.md](./논문-목차-스토리라인.md).  
파이프라인·사업자 선정: [논문-설계-노트.md](./논문-설계-노트.md).  
인용: [baseline-참고논문.md](./baseline-참고논문.md).

> 상태: **방향 합의용** (2026-11-03 재개정).  
> **한 줄:** contamination-robust **RoCA backbone** → **Shared multi-operator learning** → **expert operational calibration**.  
> **핵심 전제:** 본 연구는 contamination 신규 해법이나 backbone SOTA 경쟁을 기여로 주장하지 않는다.  
> **평가:** 연구 1은 $VUS\text{-}PR$ 중심, 연구 2는 Event-F1 · Precision/Recall · FA/day · Detection Delay 중심.  
> Point-Adjusted F1·Accuracy는 주요 지표에서 제외하고 AUROC는 보조만 사용한다.

## 1. 연구 배경 및 문제 정의

실제 이동통신 로밍 데이터에는 normal과 anomaly가 혼재되어 있어 clean normal train을 확보하기 어렵다.

또한 실제 운용 환경에는 다음 문제가 존재한다.

1. 사업자별 traffic volume, periodicity, variation, baseline, failure pattern이 서로 다르다.
2. 사업자마다 별도 TSAD를 두면 학습·배포·관리 비용이 증가하며, 사업자 간 공통 anomaly pattern을 공유하지 못한다.
3. TSAD의 statistical anomaly score가 실제 운용자가 중요하게 판단하는 operational anomaly와 반드시 일치하지 않는다.

본 연구는 contamination 자체를 새 contribution으로 해결하지 않는다.  
기존 contamination-robust TSAD를 **representative backbone**으로 사용하고, 다음 두 질문에 집중한다.

1. 이질적인 다수 로밍 사업자를 **하나의 Shared TSAD**로 학습하면 individual model 대비 anomaly score의 품질을 개선하거나 유지할 수 있는가?
2. TSAD의 statistical anomaly와 실제 operational anomaly 사이의 불일치를 **소량의 전문가 피드백**으로 줄일 수 있는가?

## 2. Contamination-Robust Backbone과 Preliminary Observation

### 2.1 Training contamination

많은 TSAD는 train data가 대부분 normal이라는 가정에 의존한다.

그러나 실제 SKT inbound roaming 데이터는 normal과 anomaly가 이미 혼재되어 있으며, 전체 train을 전문가가 사전에 정제하는 것은 시간과 비용 측면에서 현실적이지 않다.

따라서 본 연구의 출발점에는 다음 조건이 필요하다.

- contaminated train을 직접 사용할 수 있을 것
- unsupervised learning이 가능할 것
- multivariate time series를 처리할 수 있을 것
- 연속적인 anomaly score를 제공할 것
- multi-operator shared learning과 후단 calibration으로 확장 가능할 것

### 2.2 선행 연구와 본 연구의 위치

Training contamination에 따른 TSAD 성능 저하와 이를 완화하기 위한 방법은 이미 여러 연구에서 다루어졌다.

대표적으로 RiAD, RoCA, TSAD-C 등이 contaminated training을 고려한다.

따라서 본 연구는 다음을 주장하지 않는다.

- 새로운 contamination-robust 알고리즘 제안
- contamination-robust TSAD 전체의 benchmark
- 특정 backbone이 모든 TSAD보다 우수하다는 주장

Contamination 문제는 기존 robust TSAD를 활용하여 **연구의 전제조건으로 흡수**한다.

### 2.3 Backbone 선정: RoCA

본 연구의 메인 backbone으로 **RoCA**를 사용한다.

선정 이유:

- contaminated training setting을 명시적으로 고려
- unsupervised · multivariate TSAD
- continuous anomaly score 제공
- 공개 구현을 기반으로 재현 가능한 실험 구성 가능
- multi-operator shared training으로 확장 가능
- 후단 expert calibration과 분리하여 사용할 수 있음

RoCA를 선택한 이유는 “가장 높은 성능의 TSAD”이기 때문이 아니라, **본 연구의 요구조건을 만족하면서 공개 구현을 이용해 재현 가능한 contamination-robust representative backbone을 구성할 수 있기 때문**이다.

### 2.4 RiAD의 위치

RiAD는 contamination-robust TSAD의 관련 연구이자 초기 pilot comparison으로 사용한다.

현재 저장소의 RiAD 구현은 원저자의 공식 구현을 복제한 것이 아니라 논문의 핵심 역할을 practical하게 재구성한 구현이므로, 본 논문의 메인 backbone으로 성능을 직접 주장하는 데에는 재현성 리스크가 있다.

따라서:

- Related Work에서 contamination-robust 방법으로 소개
- 초기 pilot 결과는 필요 시 참고 또는 부록 수준으로 제시
- RiAD vs RoCA 자체를 본 연구의 contribution이나 대규모 bake-off로 만들지 않음

### 2.5 Preliminary Individual Result

논문용 전체 실험에 앞서 Operator 1(P0480)의 validation 구간에서 contamination-robust TSAD를 individual setting으로 적용하였다.

현재 pilot 결과:

| Model | 설정 | VUS-PR | 관찰 |
|------|------|-------:|------|
| RiAD-inspired practical implementation | Individual / valid | 약 0.03 | score ranking이 매우 약하고 false alarm이 많음 |
| RoCA | Individual / valid | 약 0.076 | RiAD보다 높지만 절대 수준은 여전히 낮음 |

RoCA는 validation의 GT anomaly event 6개 중 1개와만 overlap하였고, 약 43개의 predicted event 중 대부분이 false alarm이었다.

이 결과는 다음과 같이 해석한다.

> **RoCA 또는 contamination-robust TSAD가 일반적으로 성능이 낮다고 주장하는 것이 아니라, 본 SKT inbound roaming의 P0480 individual setting에서 기존 robust TSAD를 그대로 적용했을 때 operational GT와의 score alignment가 충분하지 않았다는 preliminary observation이다.**

특히 $VUS\text{-}PR$이 낮다는 것은 단순 threshold 선택보다 **anomaly score의 ranking 자체가 병목**임을 의미한다.

따라서 threshold 또는 percentile만 조정하여 문제를 해결하는 방향보다, 이후 연구에서 score representation과 operational decision을 각각 다른 단계에서 다룬다.

### 2.6 Preliminary Observation에서 도출되는 연구 방향

두 후속 단계의 역할을 분리한다.

```text
Individual RoCA
  ↓
낮은 score-ranking quality 관찰
  ↓
[연구 1] Shared multi-operator learning
  → 여러 사업자의 공통 정보를 이용해 statistical score 품질을 개선할 수 있는가?
  ↓
[연구 2] Expert operational calibration
  → statistical score를 실제 operational criterion에 맞출 수 있는가?
```

중요:

- **Shared가 성능을 개선한다고 사전에 주장하지 않는다.**
- Shared의 효과는 실험으로 검증할 연구 질문이다.
- 단순 threshold calibration은 $VUS\text{-}PR$을 개선하지 않으므로, 연구 1과 연구 2의 역할을 구분한다.

## 3. 연구 1 — Multi-Operator Shared Model

### 3.1 문제

개별 사업자를 각각 학습하면:

```text
Operator 1  → Individual RoCA 1
Operator 2  → Individual RoCA 2
...
Operator 10 → Individual RoCA 10
```

사업자별 데이터만 이용하게 되며 모델 수가 증가한다.

반면 여러 사업자에는 절대 traffic scale은 다르더라도 다음과 같은 공통적인 이상 형태가 존재할 가능성이 있다.

- 자신의 baseline 대비 traffic 급락/급증
- periodicity의 붕괴
- failure pattern 변화
- multivariate 관계 변화

따라서 여러 사업자의 정보를 하나의 모델에서 공유했을 때 anomaly representation의 품질이 달라지는지 검증한다.

### 3.2 Shared RoCA

```text
Operator 1 windows  ┐
Operator 2 windows  │
Operator 3 windows  ├→ One Shared RoCA
...                 │
Operator 10 windows ┘
```

사업자 raw time series를 시간축으로 직접 이어 붙이지 않는다.

사업자 $j$ 내부에서만 window를 생성한다.

$$
W_{j,t} = [x_{j,t-L+1}, \ldots, x_{j,t}]
$$

각 사업자에서 생성한 window를 하나의 training dataset으로 구성하여 Shared RoCA를 학습한다.

### 3.3 Operator-specific Normalization

사업자별 absolute scale 차이가 shared model의 학습을 지배하지 않도록 normalization은 각 사업자의 **train split만을 이용해 fit**한다.

예:

$$
z_{j,t} = \frac{x_{j,t} - \mu_j}{\sigma_j + \epsilon}
$$

또는 baseline deviation:

$$
r_{j,t} = \frac{x_{j,t} - b_{j,t}}{\sigma_{j,t} + \epsilon}
$$

목표는 사업자 간 절대 traffic 차이보다 **각 사업자가 자신의 정상 상태에서 벗어나는 상대적인 형태**를 공유 학습하는 것이다.

### 3.4 비교 실험

기본 비교:

1. **Individual RoCA**
   - 10 Operators → 10 Models

2. **Shared RoCA**
   - 10 Operators → 1 Model

필요 시 ablation:

3. **Shared RoCA + normalization variant**
   - 단, normalization 자체를 별도 신규 알고리즘으로 주장하지 않음

### 3.5 연구 질문

> Traffic volume, periodicity 및 variation이 서로 다른 다수의 로밍 사업자를 하나의 contamination-robust TSAD로 학습했을 때, individual model 대비 anomaly score의 ranking과 event detection 성능을 개선하거나 유지할 수 있는가?

### 3.6 평가

연구 1은 **score quality**가 핵심이다.

| 역할 | 지표 |
|------|------|
| **Primary** | VUS-PR |
| Event | Event-F1 |
| Additional | PR-AUC, Precision, Recall, F1 |
| Operational reference | FA/day |

각 사업자별로 지표를 계산하고 전체 평균은 macro average를 사용한다.

$$
\text{Macro Average} = \frac{1}{N}\sum_{j=1}^{N} M_j
$$

함께 보고:

- Operator별 결과
- Macro Average
- Standard Deviation

이를 통해 Shared가 일부 사업자에서만 좋아지는지, 여러 사업자에서 안정적으로 동작하는지 확인한다.

## 4. 연구 2 — Statistical ↔ Operational Alignment

### 4.1 문제

TSAD가 높은 anomaly score를 부여했다고 해서 실제 이동통신 운용에서도 반드시 중요한 anomaly는 아니다.

$$
\text{Statistical Anomaly} \neq \text{Operational Anomaly}
$$

예:

특정 failure cause가 평소 0이었다가 1건 발생하더라도 전체 attach가 20,000건이라면

$$
\frac{1}{20000} = 0.005\%
$$

에 불과하다.

통계적으로 희귀할 수 있지만 운용자가 조사해야 할 장애로 보기는 어려울 수 있다.

### 4.2 방향

```text
Shared RoCA
  ↓
Statistical Anomaly Score
  ↓
Expert Feedback + Operational Context
  ↓
Operational Calibration
  ↓
Operational Anomaly
```

### 4.3 Expert Feedback

전문가는 anomaly candidate의 score만 보는 것이 아니라 주변 context를 함께 확인한다.

예:

- attach traffic
- failure count
- failure ratio
- persistence
- baseline deviation
- 주변 시간대 pattern
- 관련 counter 변화

Feedback의 예:

- operational anomaly
- statistically unusual but operationally benign
- missed operational anomaly

### 4.4 Lightweight Operational Calibration

소량의 expert feedback으로 RoCA 전체를 다시 학습하는 대신 후단 calibration을 사용한다.

예:

$$
P(y=1 \mid s_t, r_t, v_t, p_t)
$$

- $s_t$: RoCA anomaly score
- $r_t$: failure ratio
- $v_t$: traffic volume
- $p_t$: persistence
- $y$: expert operational anomaly label

후보:

- threshold adjustment
- regularized logistic calibration
- 낮은 파라미터 수의 lightweight calibrator

### 4.5 Threshold Calibration과 Score Calibration 구분

단순히

$$
s_t > \tau
$$

의 threshold $\tau$만 조정하면:

- Precision / Recall / F1
- Event-F1
- FA/day

등은 달라질 수 있지만 **score ranking 자체는 바뀌지 않는다.**

따라서 threshold-only calibration의 핵심 목적은 operational decision 개선이며, 이 경우 $VUS\text{-}PR$ 개선을 주장하지 않는다.

반면 operational feature를 포함한 calibrator가 새로운 continuous operational score를 출력한다면 score ranking이 변할 수 있으므로, 그 경우에만 VUS-PR / PR-AUC 변화를 추가 분석할 수 있다.

### 4.6 Expert Feedback 최소화

전문가 labeling은 비용이 높으므로 feedback budget을 제한한다.

$$
0,\ 5,\ 10,\ 20,\ 40
$$

동일한 held-out evaluation protocol에서 feedback 수에 따른 성능 곡선을 비교한다.

### 4.7 연구 질문

> 기존 TSAD가 생성하는 statistical anomaly와 전문가가 판단하는 operational anomaly 사이의 불일치를 소량의 expert feedback으로 줄이면서, recall을 과도하게 희생하지 않고 false alarm 부담을 줄일 수 있는가?

### 4.8 평가

연구 2는 **operational decision quality**가 핵심이다.

| 지표 | 역할 |
|------|------|
| Event-F1 | operational event 탐지 |
| Precision / Recall | false alarm · missed anomaly 균형 |
| **False Alarms / day** | 실제 alert burden |
| **Detection Delay** | 탐지 신속성 |
| VUS-PR / PR-AUC | score가 재정렬되는 calibration인 경우에만 추가 |

비교:

```text
Shared RoCA + 기존 criterion
vs.
Shared RoCA + Expert Operational Calibration
```

## 5. 평가 프로토콜

### 5.1 Data Split

시간 순으로:

```text
Train 60% → Validation 20% → Test 20%
```

- **Train:** contaminated 상태 그대로 backbone 학습. 사람 label을 이용한 전면 사전 정제를 기본 방법으로 사용하지 않음.
- **Validation:** hyperparameter, threshold, calibration 방법 및 feedback budget 설계.
- **Test:** 모든 설계가 고정된 뒤 최종 held-out 평가.

Test label을 보면서 threshold나 calibration을 수정하지 않는다.

### 5.2 평가 지표 원칙

단일 지표의 한계를 피하기 위해 다음 세 관점을 분리한다.

1. score-ranking quality
2. event detection quality
3. operational alert quality

### 5.3 VUS-PR

$VUS\text{-}PR$은 연구 1의 primary metric이다.

역할:

- threshold-independent score quality
- temporal tolerance 고려
- imbalance 환경에서 PR 기반 평가
- Individual vs Shared의 ranking quality 비교

### 5.4 Event-F1

실제 운용에서는 point 하나보다 anomaly event를 검출했는지가 중요하므로 event-level 평가를 함께 사용한다.

### 5.5 Precision / Recall / F1

Threshold가 적용된 최종 decision의 해석을 위해 사용한다.

- Precision: false alarm과 직접 관련
- Recall: missed anomaly와 직접 관련

### 5.6 Operational Metrics

$$
\text{False Alarms/day}
=
\frac{\#\text{False Alarm Events}}{\text{Observation Days}}
$$

$$
\text{Detection Delay}
=
t_{\text{detected}} - t_{\text{start}}
$$

### 5.7 사용하지 않음 / 보조만

| 지표 | 정책 |
|------|------|
| **Point-Adjusted F1** | 주요 지표에서 제외 |
| **Accuracy** | 사용하지 않음 |
| **AUROC** | 필요 시 보조만 |
| Best-F1 oracle | 분석용 상한으로만 사용하며 primary 결과로 사용하지 않음 |

## 6. Contribution

본 연구의 contribution은 최대 세 가지로 제한한다.

1. **Shared Multi-Operator TSAD**  
   실제 inbound roaming의 이질적인 다수 사업자를 대상으로 contamination-robust TSAD를 individual model과 shared model로 구성하고, 사업자별 및 macro-level 성능을 비교한다.

2. **Expert-based Operational Alignment**  
   statistical anomaly와 실제 이동통신 operational anomaly 사이의 불일치를 분석하고, 소량의 expert feedback과 operational context를 이용한 lightweight calibration을 적용한다.

3. **Operational Evaluation on Real Telecom Data**  
   실제 이동통신 로밍 데이터에서 score-ranking, event-level, operational alert 관점을 분리하여 VUS-PR, Event-F1, FA/day, Detection Delay 등을 함께 평가한다.

Contamination-robust 학습 자체는 contribution으로 주장하지 않는다.

## 7. 주장 범위와 리뷰어 방어

| 예상 질문 | 본 연구의 답변 |
|----------|----------------|
| “RoCA 성능이 낮은데 왜 backbone으로 사용하는가?” | RoCA의 SOTA 우위를 주장하는 연구가 아니다. 공개 구현을 가진 contamination-robust representative backbone을 실제 roaming setting에 적용하고, standalone 한계를 관찰한 뒤 sharing과 operational adaptation의 효과를 검증한다. |
| “왜 다른 SOTA 모델을 더 비교하지 않았는가?” | Backbone benchmark가 연구 목적이 아니다. 연구 범위를 contamination-robust backbone 위의 multi-operator sharing과 operational alignment로 제한한다. |
| “Shared가 단순히 데이터를 더 많이 넣은 것 아닌가?” | 동일 backbone을 유지한 Individual vs Shared 비교와 사업자별/Macro/Std 결과를 통해 cross-operator sharing의 효과와 trade-off를 평가한다. |
| “사업자 분포가 다른데 하나의 모델로 합치는 것이 타당한가?” | 사업자별 train-only normalization을 사용하고, 각 사업자 내부에서만 window를 생성하여 존재하지 않는 cross-operator temporal adjacency를 만들지 않는다. |
| “Expert calibration은 supervised classifier 아닌가?” | 전체 TSAD를 재학습하는 조밀 supervised model이 아니라, 기존 statistical score를 소량의 feedback으로 operational criterion에 맞추는 lightweight 후단 단계로 한정한다. |
| “Calibration이 VUS-PR을 개선하는가?” | Threshold-only calibration은 ranking을 바꾸지 않으므로 VUS-PR 개선을 주장하지 않는다. Operational metrics 개선이 핵심이다. |

        ↓
