파이프라인 세부(분할·라벨·run)는 [논문-설계-노트.md](./논문-설계-노트.md),

> 상태: **방향 합의용 초안** (2026-09-25 개정).  
> 핵심 주장: **순수 비지도 TSAD의 IB 한계를 분석**하고, 그 대안으로 **완전 지도가 아니라 준지도·설명 가능 규칙(통신향 multi-metric Argos)** 을 제안한다.

---

## 1. 한 줄 메시지 (포지셔닝)

IB inbound roaming의 사람 GT는 통계적 outlier가 아니라 **운영상 품질 이상**(rate / attempt / fail)이다.  
이 설정에 대표 **비지도** TSAD를 적용하면, 특히 **mild** 구간에서 재구성·점수 모델이 이상을 정상처럼 취급하기 쉽다.  
따라서 “라벨을 많이 쓰는 완전 지도 분류”보다, **도메인 축에 맞춘 준지도·규칙 기반 AD**가 더 적합하다.  
본 논문은 그 실증과 함께, 단변량 Argos를 **multi-metric으로 융합한 통신향 Argos**를 제안한다.

---

## 2. 왜 “완전 지도”가 아닌가

| 선택지 | 본 논문에서의 위치 |
|--------|-------------------|
| **비지도** (OA, AT, LSTM-AD, Classical 등) | 한계를 **보이기 위한 비교군** (primary thr는 label-free) |
| **완전 지도** (윈도우 분류기 등) | **주장이 아님.** 라벨 비용·미라벨 PLMN·“그냥 GBDT면 되지?”에 취약 |
| **준지도 / 규칙** (Argos·heuristic 축별 규칙) | **제안.** 라벨·도메인 prior로 규칙을 만들되, 배포 시 규칙만 실행·설명 가능 |

한 줄: *비지도의 한계 → 지도가 답* 이 아니라, *비지도의 한계 → **축이 분명한 준지도 규칙(통신향 Argos)** 이 답*.

| **GT** | 사람 라벨은 운영 의미 기준 ([라벨링-원칙.md](./라벨링-원칙.md)). rate는 스크리닝 렌즈이지 GT의 유일 정의가 아니다. |

| **시사점** | (1) mild에서 재구성 계열 score가 정상대에 머무는 사례, (2) severe는 classical/규칙과도 상당수 겹침 → **순수 비지도 딥의 추가 이득이 제한적**일 수 있음. |

| **제안** | Argos(단변량 규칙)를 IB 핵심 metric에 병렬 적용하고 융합하는 **통신향 multi-metric Argos**. |
| **기여** | (1) IB AD 설정·라벨 원칙, (2) 비지도 TSAD의 IB 한계 분석, (3) 준지도 통신향 Argos 제안·비교. |

## 4. 비지도 TSAD를 IB에 적용했을 때의 문제점 (분석 축)

기존 [OmniAnomaly-관찰.md](./OmniAnomaly-관찰.md)를 논문의 **문제 제기 근거**로 쓴다. 모델 보편 단정은 피하고 설정을 한정한다.

### 4.1 Mild 운영 이상

- 패턴: `rate_degrade` / `attempt_*` 중심, fail 폭증 약함.
- 비지도 재구성(예: OA): mild를 **잘 복원** → score가 thr 아래로 안 떨어짐 → 탐지 실패.
- 해석: “모델이 나빠서”가 아니라 **inductive bias가 운영 GT와 어긋남**.

### 4.2 Severe multivariate collapse

- rate 붕괴 + attempt·fail 동시 폭증 → 비지도도 score가 크게 반응.
- 다만 같은 구간은 **IQR/EWMA·단일 축 규칙**으로도 상당수 재현 가능 → 복잡한 비지도 모델의 **추가 이득이 작을 수 있음**.

### 4.3 평가 함정

- 긴 severe 한 방에 point recall이 부풀 수 있음 → **point + event** 동시 보고.
- mild vs severe(또는 `reasons` 코드) **breakdown**이 시사점의 본문.

### 4.4 함의 (지도가 아니라 준지도로)

비지도만으로는 운영 GT(특히 mild)를 충실하기 어렵다.  
그렇다고 즉시 완전 지도로 갈 필요는 없다. IB 이상은 **소수 KPI 축**으로 설명되는 경우가 많아, **축별 규칙 + (선택적) 라벨 기반 규칙 학습**이 비용·설명·배포 면에서 더 맞다.

## 5. 제안: 통신향 Argos (multi-metric ensemble)

### 5.1 “통신 튜닝”의 정의

- Argos 원본은 **단변량** 규칙 (`inference(value, index) → {0,1}`).
- IB 이상은 한 시계열에만 있지 않음 → **핵심 metric마다 Argos(또는 동일 계약 heuristic)를 두고 출력을 융합**.
- “튜닝” ≠ LLM이 통신을 알아서 이해함.  
  **= 도메인 축 선택 + 단변량 Argos 병렬 + 융합 규칙.**

### 5.2 축 (라벨 원칙과 정렬)

| 축 | 예 | 역할 |
|----|-----|------|
| Rate 급락 | `A_RATE` (필요 시 `S_RATE`) | 스크리닝·mild rate_degrade |
| Attempt | `M971` | 급증/급락 |
| Fail / TO | 라벨 `fail_metrics`에 **실제로 찍힌** 지표만 | 동반 확인·폭증 |

구현: `Argos_ib/` (`ensemble.py`, `--with-fails`는 라벨  deriv fail만).

### 5.3 융합

| 방식 | 정의 | 비고 |
|------|------|------|
| **OR** | 어느 축이라도 fire → anomaly | 1차 기본 |
| **sum / thr** | `#axes` ≥ k | soft score에 가깝게 |
| **two_stage** | (rate∪attempt) 후보 ∩ fail 확인 | 라벨 워크플로와 유사; mild만 rate인 경우는 OR이 더 맞을 수 있음 |

UI score 예: \(s_t = -\#\{\text{axes firing}\}\) (낮을수록 이상).

### 5.4 공정 비교 (필수 표기)

| | 비지도 비교군 | 통신향 Argos |
|--|---------------|--------------|
| 정보 | train 정상 패턴 (+ label-free thr) | 규칙 학습 시 **라벨·도메인 prior (준지도)** |
| Primary | POT / percentile 등 | 규칙·융합 정의 |
| 서술 | unsupervised | **semi-supervised / rule-based** |

표·본문에 정보량 차이를 명시한다. “무조건 SOTA”보다 **mild에서의 적합·설명 가능성**을 전면에.

## 6. 비교 모델 — 분야별 대표 1픽

Related Work는 넓게, **Experiment는 1픽 + 제안**만.

| 분야 | 대표 1픽 | 이 논문에서의 역할 |
|------|----------|-------------------|
| Classical | **IQR + EWMA** (`Classical/`) | 비지도 하한 · “severe는 단순 통계로도?” |
| Forecasting | **LSTM-AD** (`LSTM_AD/`) | 예측 잔차 inductive bias |
| Reconstruction | **OmniAnomaly** | 비지도 한계(mild 복원)의 중심 근거 |
| Transformer | **Anomaly Transformer** | association / attention 비지도 |
| 준지도 규칙 (제안) | **Argos multi-metric** (`Argos_ib/`) | 시사점에 대한 응답 |

여유 시 ablation: USAD, TranAD.  
**권고:** 1픽·Argos가 안정되기 전에는 넣지 않음.

코드: OmniAnomaly · AnomalyTransformer · Classical · LSTM_AD · Argos_ib.

## 7. 권장 / 비권장 문장

**권장**

- “본 IB 설정에서 비지도 재구성 모델은 severe에는 반응했으나 mild 운영 이상에서 score가 정상대에 머무는 사례가 관찰되었다.”
- “severe는 단순 baseline과도 겹칠 수 있어, 비지도 딥의 추가 이득이 제한적일 수 있다.”
- “해석 가능 KPI 축이 있는 IB에서는 **준지도·축별 규칙(통신향 Argos)** 이 비지도 다변량 점수보다 운영 GT에 더 잘 맞을 수 있다.”

**비권장**

- “비지도는 실패했으므로 **지도 학습이 답이다**.” (완전 지도로 비약)
- “OmniAnomaly는 항상 극단만 잡는다.” (모델 보편 단정)
- 정보량 차이 없이 “Argos가 모든 비지도보다 우수하다.”
