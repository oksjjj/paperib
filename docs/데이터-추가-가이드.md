# 데이터 추가 후 해야 할 일

원본 CSV는 `data/`에만 두고, 웹(GitHub Pages)에는 `docs/viewer/data/`로보낸 결과만 올립니다.  
데이터가 늘어나면 **로컬 캐시 재구축 → 뷰어 export → git push** 순서로 반영합니다.

앞으로 `data/`에 넣는 파일은 `top100.txt`에 있는 사업자만 포함한다고 가정합니다.

## 한눈에 보기

| 경로 | git push | 설명 |
|------|----------|------|
| `data/masked_*.csv` | ❌ | 일자별 원본 (gitignore) |
| `data/plmn_mapping.txt` | ❌ | PLMN 역매핑 (로컬 라벨링용) |
| `data/metric_mapping.txt` | ❌ | 지표 역매핑 (로컬 라벨링용) |
| `labeling/cache/*.pkl` | ❌ | 라벨링 앱용 캐시 |
| `labeling/labels/*_labels.json` | ❌ | 로컬 anomaly 라벨 |
| `docs/viewer/data/*.json` | ✅ | **라벨링** 탭 export (`data/`) |
| `docs/viewer/data-top100/*.json` | ✅ | **Top 100** 탭 export (`data-top100/`) |
| `docs/viewer/app.js` 등 | ✅ | 정적 뷰어 UI (탭 포함) |

`preprocess`는 라벨 JSON을 지우거나 초기화하지 **않습니다**.

## 저장소 루트에서 실행

```bash
cd /path/to/paperib
source .venv/bin/activate   # 또는 .venv/bin/python 으로 실행
```

### 1) 원본 데이터 · mapping 추가

`data/`에 CSV와 역매핑(선택)을 넣습니다. 예:

```text
data/masked_YYYYMMDD.csv
data/plmn_mapping.txt      # masked_plmn ↔ original_plmn (TSV)
data/metric_mapping.txt    # masked_metric ↔ original_metric (TSV)
```

웹 뷰어 export에는 mapping이 포함되지 않습니다.

### 2) 로컬 캐시 재구축

```bash
python labeling/preprocess.py
```

- 기본값: `top100.txt` 사업자만 캐시
- `labeling/cache/{PLMN}.pkl`, `labeling/labels/plmn_rank.csv` 갱신
- data fingerprint가 같으면 이미 최신인 pickle은 skip

강제 전체 재생성:

```bash
python labeling/preprocess.py --force
```

### 3) 웹 뷰어용 JSON export

**GitHub Pages에 올릴 때 (라벨링 + Top 100 탭 모두):**

```bash
python labeling/export_viewer.py --catalog both
```

| 옵션 | 출력 | 용도 |
|------|------|------|
| **(기본)** | `data/` + `data-top100/` | 라벨링 + Top 100 둘 다 |
| `--catalog labeled` | `docs/viewer/data/` | 라벨 있는 사업자만 · 고해상도 |
| `--catalog top100` | `docs/viewer/data-top100/` | `top100.txt` 100개 · 샘플링 (기본 5000 pts) |

- 라벨링: 로컬 라벨을 JSON에 임베드 (mapping 없음)
- Top 100: anomaly UI 없음 · **M971 시각별 평균 참조선** (`m971_tod_ref`) 포함
- `app.js` / `style.css`에 `?v=` 캐시 버스팅

라벨링만 갱신:

```bash
python labeling/export_viewer.py --catalog labeled
```

Top 100만 갱신:

```bash
python labeling/export_viewer.py --catalog top100
```

로컬에서 확인:

```bash
cd docs/viewer && python -m http.server 8765
# → http://127.0.0.1:8765/
```

### 4) GitHub Pages에 반영

```bash
python labeling/export_viewer.py
git add docs/viewer/
git status
git commit -m "Update viewer export with latest data"
git push
```

`data-top100/`는 기본 export에 포함됩니다. 이 폴더 없이 push하면 Pages에서 **Top 100** 탭만 비어 있습니다.

몇 분 후 Pages URL에서 확인합니다.

```text
https://<user>.github.io/<repo>/viewer/
```

## 라벨링 앱만 쓸 때

웹 게시 없이 로컬 라벨링만 하면 **2) preprocess**까지면 됩니다.

```bash
python labeling/preprocess.py
python labeling/app.py
```

## 자주 하는 오해

- **`data/`에 넣기만 하면 웹에 보이나?**  
  → 아닙니다. `export_viewer.py` + `docs/viewer/` push가 필요합니다.

- **preprocess 하면 anomaly 라벨이 사라지나?**  
  → 아닙니다. `*_labels.json`은 그대로입니다.

- **왜 CSV를 100개가 아니라 날짜 파일 개수만큼 읽나?**  
  → `data/`는 사업자별이 아니라 **일자별** 파일이라, 전 기간 캐시를 만들려면 날짜 파일을 모두 훑습니다.

## 관련 파일

- `top100.txt` — 캐시/뷰어 대상 사업자 목록
- `labeling/preprocess.py` — 캐시·랭킹 재구축
- `labeling/export_viewer.py` — Pages용 JSON export
- `docs/viewer/README.md` — 뷰어 UI·Pages 설정 상세
