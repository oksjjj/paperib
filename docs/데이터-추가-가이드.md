# 데이터 추가 후 해야 할 일

로컬에서 라벨링 앱을 여는 방법은 [로컬-실행-가이드.md](로컬-실행-가이드.md)를 참고하세요.

원본 CSV는 `data/`에 둡니다. 데이터가 늘어나면 **로컬 캐시 재구축** 후 라벨링 앱을 쓰면 됩니다.

앞으로 `data/`에 넣는 파일은 `top100.txt`에 있는 사업자만 포함한다고 가정합니다.

## 한눈에 보기

| 경로 | git push | 설명 |
|------|----------|------|
| `data/ib_data/raw/masked_*.csv` | ❌ | 일자별 원본 (gitignore) |
| `data/ib_data/raw/plmn_mapping.txt` | ❌ | PLMN 역매핑 (로컬 라벨링용) |
| `data/ib_data/raw/metric_mapping.txt` | ❌ | 지표 역매핑 (로컬 라벨링용) |
| `labeling/cache/*.pkl` | ❌ | 라벨링 앱용 캐시 |
| `data/ib_data/labels/*_labels.json` | ✅ | anomaly 라벨 (원본 · git 추적) |

`preprocess`는 라벨 JSON을 지우거나 초기화하지 **않습니다**.

## 저장소 루트에서 실행

```bash
cd /path/to/paperib
source .venv/bin/activate   # 또는 .venv/bin/python 으로 실행
```

### 1) 원본 데이터 · mapping 추가

`data/`에 CSV와 역매핑(선택)을 넣습니다. 예:

```text
data/ib_data/raw/masked_YYYYMMDD.csv
data/ib_data/raw/plmn_mapping.txt      # 로컬 전용 · git 금지
data/ib_data/raw/metric_mapping.txt    # 로컬 전용 · git 금지 (masked↔원본 대응)
```

> **보안:** `*_mapping.txt`와 masked ID↔원본 metric/PLMN명 대응은 **문서·주석·커밋에 넣지 않는다.** 로컬 라벨링 UI에서만 읽는다.
### 2) 로컬 캐시 재구축

```bash
python labeling/preprocess.py
```

- 기본값: `top100.txt` 사업자만 캐시
- `labeling/cache/{PLMN}.pkl`, `data/ib_data/labels/plmn_rank.csv` 갱신
- data fingerprint가 같으면 이미 최신인 pickle은 skip

강제 전체 재생성:

```bash
python labeling/preprocess.py --force
```

### 3) 라벨링 앱 실행

```bash
python labeling/preprocess.py
python labeling/app.py
```

## 자주 하는 오해

- **preprocess 하면 anomaly 라벨이 사라지나?**  
  → 아닙니다. `*_labels.json`은 그대로입니다.

- **왜 CSV를 100개가 아니라 날짜 파일 개수만큼 읽나?**  
  → `data/`는 사업자별이 아니라 **일자별** 파일이라, 전 기간 캐시를 만들려면 날짜 파일을 모두 훑습니다.

## 관련 파일

- `top100.txt` — 캐시 대상 사업자 목록
- `labeling/preprocess.py` — 캐시·랭킹 재구축
- `labeling/app.py` — 로컬 라벨링 UI
