## 2. 장별 핵심 메시지

### 1. 서론

실제 inbound roaming 데이터에는 clean-normal assumption이 성립하기 어렵고, 여러 사업자의 분포가 다르며, statistical anomaly와 operational anomaly가 일치하지 않는다.

본 연구는 contamination 자체를 새로 해결하지 않고 기존 robust backbone을 활용하여:

1. multi-operator sharing
2. expert operational alignment

에 집중한다.

### 2. 관련 연구

관련 연구를 네 축으로 정리한다.

- contamination-robust TSAD
- multi-entity/shared modeling
- expert feedback / human-in-the-loop
- TSAD evaluation

RiAD/RoCA 비교 자체를 연구 contribution으로 만들지 않는다.

### 3. 데이터 및 문제 설정

여기서 반드시 명확히 기술한다.

- 5분 시계열
- 10개 operator 선정 기준
- 사업자 익명화
- operational GT 정의
- chronological 60/20/20
- train-only normalization
- contaminated train을 기본으로 사용
- test held-out

### 4. 제안 프레임워크

#### 4.1 RoCA backbone

RoCA를 선택한 이유는 SOTA이기 때문이 아니라:

- contamination 고려
- multivariate
- unsupervised
- continuous score
- 공개 구현
- shared/calibration 확장 가능

때문이라고 명시한다.

#### 4.2 Preliminary observation

P0480 Individual 결과에서:

- RoCA VUS-PR 약 0.076
- GT event 6개 중 1개 overlap
- predicted event 약 43개 중 대부분 false alarm

을 관찰했다.

이 결과를 RoCA의 일반적 실패로 단정하지 않고:

> 본 roaming setting에서 standalone application의 한계가 관찰되었다.

라고 서술한다.

#### 4.3 Shared multi-operator

Individual vs Shared를 비교한다.

핵심 질문:

> 여러 사업자의 공통 정보를 공유하면 anomaly score ranking과 event detection이 개선되거나 유지되는가?

주 지표:

- VUS-PR
- Event-F1
- PR-AUC
- Operator-wise / Macro / Std

#### 4.4 Operational calibration

Shared RoCA score를 expert feedback과 operational context로 보정한다.

핵심 질문:

> 소량의 expert feedback으로 false alarm을 줄이면서 recall을 유지할 수 있는가?

주 지표:

- Event-F1
- Precision
- Recall
- FA/day
- Detection Delay

Threshold-only calibration이면 VUS-PR 개선을 주장하지 않는다.

### 6. 결론

기여를 과장하지 않는다.

- contamination 신규 알고리즘이 아님
- RoCA SOTA 주장 아님
- unseen operator generalization 주장 아님
- 고트래픽 10개 operator에 대한 실제 환경 실증

## 3. Contribution 초안

최대 3개로 유지한다.

1. **Shared Multi-Operator TSAD**  
   이질적인 다수 inbound roaming operator를 contamination-robust backbone으로 individual/shared 학습하고 operator-wise 및 macro-level 성능을 비교한다.

2. **Expert-based Operational Alignment**  
   statistical anomaly와 operational anomaly 사이의 차이를 소량 expert feedback과 operational context를 이용한 lightweight calibration으로 보정한다.

3. **Operational Evaluation on Real Telecom Data**  
   실제 이동통신 데이터에서 VUS-PR, Event-F1, FA/day, Detection Delay 등을 이용하여 score quality와 operational usefulness를 분리 평가한다.

## 5. 작성 시 금지/주의 표현

### 피할 표현

- “RoCA는 SKT에서 우수한 성능을 보였다.”
- “Shared model은 성능을 향상시킨다.” — 결과 확인 전
- “본 연구는 contamination 문제를 해결한다.”
- “RoCA보다 RiAD가 열등하다.”
- “전문가 calibration이 VUS-PR을 개선한다.” — threshold-only일 경우

### 권장 표현

- “RoCA를 representative contamination-robust backbone으로 사용하였다.”
- “P0480 individual setting에서 operational GT와의 alignment가 충분하지 않은 preliminary observation을 얻었다.”
- “Shared learning의 효과를 검증하였다.”
- “Expert calibration의 목적은 statistical score를 operational criterion에 맞추는 것이다.”
- “Threshold-only calibration에서는 ranking metric 개선을 주장하지 않는다.”

## 6. 평가 지표 역할

| 연구 단계 | Primary / 핵심 |
|----------|----------------|
| Preliminary | VUS-PR + Event-F1 + FA/day |
| Shared | **VUS-PR**, Event-F1, PR-AUC, Macro+Std |
| Calibration | **Event-F1, Precision/Recall, FA/day, Detection Delay** |

공통 정책:

- PA-F1 primary 제외
- Accuracy 미사용
- AUROC 보조
- Best-F1 oracle은 분석용 상한

## 7. 한계

논문에서 미리 인정할 범위:

- 고트래픽 중심 10개 operator
- 단일 메인 backbone(RoCA)
- 동일 10개 known operator의 future split 평가
- unseen operator generalization은 직접 검증하지 않음
- expert label 수가 제한적일 수 있음
- 기업 데이터 특성상 raw PLMN/사업자명 비공개
