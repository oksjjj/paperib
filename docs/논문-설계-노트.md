# IB Inbound Roaming — 논문용 설계 노트

연구 파이프라인(데이터 · 라벨 · 모델 · 평가)에서 지금까지 합의·반영한 **주요 설계**를 정리한다.  
세부 라벨 규칙은 [라벨링-원칙.md](./라벨링-원칙.md), COMB run은 [OmniAnomaly/COMB_RUNS.md](../OmniAnomaly/COMB_RUNS.md)를 본다.

> **보안:** masked ID(`P####`, `M###`) ↔ 원본명의 대응은 git·논문 초안에 넣지 않는다 (로컬 mapping만).

---

## 1. 문제 설정

- **도메인:** inbound roaming 제어면 시계열 (5분 샘플).
- **목표:** 운영상 의미 있는 **품질 이상**(접속 시도·성공/수락률·실패/타임아웃 등)을 multivariate 모델로 탐지하고, 사람 라벨과 비교한다.
- **비목표:** “통계적으로 평균에서 벗어난 모든 포인트”를 이상으로 두지 않는다. 운용에 무관한 counter 변동은 학습·평가에서 배제한다.

---

## 2. 데이터 · 분할

| 항목 | 설계 |
|------|------|
| 샘플 간격 | **5분** |
| 분할 | 시간 순 **train 60% / valid 20% / test 20%** (기본) |
| scaler | train만 fit (MinMax 등), valid/test는 transform |
| 사람 라벨 ∩ train | 비지도 학습에서 **해당 구간은 학습에서 제외** (`drop_labeled_from_train`) |
| valid | POT·임계값·F1·라벨링 UI 오버레이 |
| test | **held-out**. 튜닝을 보며 맞추지 않음. 최종 보고용 |

라벨링 UI에는 TRAIN / VALID / TEST 밴드를 표시한다.

---

## 3. Feature 뷰 (run)

세 가지 run을 분리해 산출물(체크포인트·예측 JSON)이 서로 덮어쓰지 않게 한다.

| run | 입력 | 표준화 | 역할 |
|-----|------|--------|------|
| **`paperib`** | 전체 raw counter (**기본 제외: M688**) | MinMax (train fit) | full multivariate baseline |
| **`comb`** | 품질 관련 raw 14개 + SUCCESS/ACCEPT rate | MinMax | 운용 해석 가능한 소수 feature |
| **`comb_share`** | M971 + (나머지 counter ÷ M971) | M971: log1p→MinMax; share: MinMax | 시도량 대비 **비율** 중심 |

### 3.1 `paperib`에서 M688 제외 (기본)

- **현상:** train 구간에서는 거의 0에 가깝고, valid/test에만 간헐적으로 최대 수 건 수준으로 나타남.
- **판단:** 운용상 중요하지 않으며, train에 패턴이 없어 모델이 valid/test의 희소 spike에 과민해질 수 있음.
- **반영:** `OmniAnomaly/run_plmn.py`의 `EXCLUDED_TRAIN_METRICS = {"M688"}`. Anomaly Transformer도 동일 `prepare_arrays`를 쓰므로 함께 적용.
- **UI:** 라벨링 화면의 metric 목록에서는 계속 볼 수 있음 (학습 입력만 제외).
- COMB run 목록에는 원래 M688이 없음.

`window_length` ≠ 100이면 경로에 `_w{N}`을 붙여 기본 win=100 산출물과 분리한다.

## 4. 사람 라벨 (GT)

### 4.1 정의 원칙

- 라벨은 모델 출력이 아니라 **운영·연구상 이상으로 합의한 구간**.
- **SUCCESS/ACCEPT rate는 스크리닝 렌즈**이지, 라벨의 유일한 정의가 아니다.  
  rate만으로 자동 GT를 만들면 multivariate 평가가 “성공률 급락 탐지”로 붕괴한다.
- **성공률·수락률이 일시적으로만 비정상적으로 올라갔다가 회복**하는 구간은 이상으로 두지 않는다 (“좋은 쪽 이탈”).
- 확정 전 FAIL/TO 등 **동반 신호**를 확인한다. rate는 애매한데 실패 계열만 튀는 구간도 valid/test에 일부 포함한다.

### 4.2 형식 · 판정 기준

- **구간(range) 우선**, 점은 순간 이벤트만.
- 저장: `data/ib_data/labels/{PLMN}_labels.json`
- 라벨마다 판정 기준(`reasons`, 복수 가능) + 선택적 메모:

| 코드 | 의미 |
|------|------|
| `rate_degrade` | SUCCESS/ACCEPT rate 급락 및/또는 낮은 지속 |
| `attempt_drop` / `attempt_spike` | M971 급락 / 급증 |
| `fail_surge` | 실패·타임아웃 폭증 → `fail_metrics`에 해당 지표(복수) |
| `other` | 기타 (메모 권장) |

- ~~`multi_collapse`~~ 는 사용하지 않음 (rate / attempt / fail로 충분).

세부·예시: [라벨링-원칙.md](./라벨링-원칙.md).

### 4.3 라벨링 UI (요지)

- rate 패널 + raw counter, 드래그 줌 시 Y 자동.
- 사람 라벨(금) / 모델 예측(보라) 오버레이, 기여 metric.
- 판정 기준 체크 · fail 지표 멀티선택 · 메모 (전환·Save 시 반영).
- 구간 편집: 경계선 드래그, **5분 스냅**.

## 5. 모델 · 점수 · 임계값

### 5.1 OmniAnomaly

- 비지도 VAE + planar NF 등 (벤더 코드 기반).
- 점수: reconstruction log-prob 계열 → **낮을수록 이상** (`score < threshold`).
- valid에서 POT (및 필요 시 best-F1)로 임계값·구간 export.
- train 사람 라벨 구간은 학습에서 제외.

### 5.2 Anomaly Transformer

- Association discrepancy 기반 (ICLR’22).
- UI 호환을 위해 **stored_score = −energy** (높을수록 정상; `score < 0` ≈ energy threshold).
- Omni와 동일 분할·run_name(`paperib` / `comb` / `comb_share`).

### 5.3 평가 역할 분리

| 구간 | 사용 |
|------|------|
| Train | 정상 패턴 학습 (라벨 구간 drop) |
| Valid | 임계값·탐지 지표·UI 비교·튜닝 |
| Test | 최종 held-out (튜닝 후 1회) |

## 6. 논문/보고에 명시할 문장 (초안)

1. **GT:** 운영상 품질 이상. rate로 후보를 찾고 FAIL/TO·시도량 등으로 확인하며, rate 단독 임계값으로 GT를 만들지 않았다.  
2. **성공률 급등:** 일시적 상승 후 회복은 이상으로 라벨하지 않았다.  
3. **분할:** chronological 60/20/20. 사람 라벨이 있는 train 구간은 비지도 학습에서 제외.  
4. **Feature:** (a) full raw minus M688, (b) COMB raw+rates, (c) COMB share(÷M971).  
5. **M688:** train에 거의 없고 valid/test에만 희소하며 운용 비중요 → full-raw 학습에서 제외.  
6. **평가:** valid로 임계값·지표를 정하고, test는 held-out으로 보고한다.
