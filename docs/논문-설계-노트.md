# IB Inbound Roaming — 논문용 설계 노트

연구 파이프라인(데이터 · 라벨 · 모델 · 평가)의 현재 설계를 정리한다.  
**논문 스토리:** [논문-스토리라인.md](./논문-스토리라인.md).  
**목차:** [논문-목차-스토리라인.md](./논문-목차-스토리라인.md).  
**관련 연구:** [baseline-참고논문.md](./baseline-참고논문.md).  
세부 라벨 규칙: [라벨링-원칙.md](./라벨링-원칙.md).

> **보안:** masked ID(`P####`, `M###`) ↔ 원본 사업자/지표명의 대응은 git·논문 초안에 넣지 않는다.  
> **현재 메인 방향:** contamination-robust **RoCA backbone** → **Shared multi-operator** → **expert operational calibration**.

---

## 1. 문제 설정

- **도메인:** SKT inbound roaming 제어면 multivariate time series, 5분 샘플.
- **운용 목표:** 접속 시도·성공/수락률·실패/타임아웃 등의 변화 중 실제 운영자가 확인해야 하는 품질 이상을 탐지한다.
- **연구 목표:**
  1. 공개 구현을 가진 contamination-robust **RoCA**를 representative backbone으로 사용한다.
  2. 여러 사업자를 하나의 **Shared RoCA**로 학습할 수 있는지 검증한다.
  3. statistical anomaly score와 operational anomaly 사이의 차이를 소량 expert feedback으로 calibration한다.
- **비목표:**
  - contamination 신규 알고리즘 제안
  - backbone SOTA benchmark
  - 모든 통계적 outlier를 operational anomaly로 정의
  - 완전 지도 분류기로 문제를 대체

### 1.1 사업자 선정 기준

전체 로밍 사업자 중 **10개**를 선정한다.

| 기준 | 내용 |
|------|------|
| 트래픽 규모 | 운용 중요도가 높은 상위 트래픽 사업자 우선 |
| 국가 중복 금지 | 동일 국가 사업자 중복 선정 없음 |
| 다양성 | 서로 다른 10개 국가의 사업자 |

선정 국가는 중국, 네덜란드, 네팔, 필리핀, 스웨덴, 오스트리아, 베트남, 캄보디아, 미국, 미얀마이다.

목적은 사업자 수 자체를 늘리는 것이 아니라 volume·periodicity·variation·baseline·failure pattern이 서로 다른 시계열을 포함하여 **Shared model의 이질성 대응 능력**을 평가하는 것이다.

**논문 표기**

- 실제 PLMN 및 사업자명은 공개하지 않는다.
- 본문에서는 `Operator 1` … `Operator 10`으로 익명화한다.
- 필요 시 국가만 병기한다.
- 고트래픽 사업자 중심 결과이므로 저트래픽 사업자 전체에 대한 일반화는 주장하지 않는다.

## 2. 데이터 · 분할

| 항목 | 설계 |
|------|------|
| 샘플 간격 | 5분 |
| 분할 | chronological **train 60% / valid 20% / test 20%** |
| scaler | 각 사업자의 **train split에만 fit**, valid/test에는 transform |
| train label 사용 | backbone 학습 전에 anomaly label로 train을 전면 정제하지 않음 |
| valid | HP · threshold · shared 설계 · calibration 설계 |
| test | 모든 설계 확정 후 최종 held-out 평가 |

### 2.1 Contaminated train 원칙

본 논문의 출발점은 실제 train data에 normal과 anomaly가 혼재한다는 것이다.

따라서 기본 실험에서는 사람 label을 이용해 anomaly 구간을 사전에 제거하지 않는다.

```text
Train
= 실제 contaminated sequence
→ RoCA 학습

Validation / Test label
= 평가 및 calibration 설계에 사용
```

기존 hard-drop 방식이 코드에 남아 있더라도 **primary experiment로 사용하지 않는다**. 필요하면 sensitivity analysis 수준으로만 사용할 수 있다.

### 2.2 Data leakage 방지

- scaler는 train에만 fit
- valid에서 HP/threshold/calibration 확정
- test는 최종 평가 전까지 tuning에 사용하지 않음
- 여러 사업자를 shared 학습하더라도 사업자 간 raw time series를 직접 이어 붙이지 않음

## 3. Feature 및 Normalization

### 3.1 현재 primary feature

현재 primary run은 **전체 raw counter**를 사용한다.

- P0480 기준 약 46차원
- rate overlay는 labeling/운용 해석에 사용할 수 있지만 primary backbone 입력은 raw counter 중심
- metric별 임의 사전 제거는 기본적으로 하지 않음

현재 구현 기준:

```text
Operator j raw counters
        ↓
train-fit scaler
        ↓
sliding windows
        ↓
RoCA
```

### 3.2 Shared model용 normalization

Shared model에서는 사업자별 절대 traffic scale 차이가 학습을 지배하지 않도록 **operator-specific train normalization**을 사용한다.

현재 구현의 MinMax normalization을 기본으로 하며, 필요 시 다음 방식은 ablation 후보로 둔다.

$$
z_{j,t} = \frac{x_{j,t}-\mu_j}{\sigma_j+\epsilon}
$$

또는 baseline-relative representation:

$$
r_{j,t} = \frac{x_{j,t}-b_{j,t}}{\sigma_{j,t}+\epsilon}
$$

단, normalization 자체를 별도 신규 알고리즘 contribution으로 주장하지 않는다.

### 3.3 Feature ablation

과거의 `comb`, `comb_share` 등 feature view는 현재 메인 실험 설계에서 제외한다.

필요한 경우에만 다음 목적의 **보조 ablation**으로 다시 도입한다.

- full raw feature의 과다/희소 feature 영향 확인
- volume 대비 failure ratio 등 operational representation 효과 확인

메인 논문 스토리는 feature engineering이 아니라 **Shared learning + Operational calibration**이다.

## 4. 사람 라벨 (Operational GT)

### 4.1 정의

라벨은 단순한 statistical outlier가 아니라 **운영상 확인이 필요한 품질 이상 구간**을 의미한다.

핵심 원칙:

- SUCCESS/ACCEPT rate는 anomaly 후보를 찾는 screening signal일 수 있으나 GT의 유일한 정의가 아니다.
- FAIL/TO, attempt 변화, 지속성, 주변 context를 함께 확인한다.
- 단순한 희귀성이나 0→1 같은 미미한 count 변화만으로 anomaly로 정의하지 않는다.
- 구간(range) labeling을 우선한다.

### 4.2 라벨 reason

| 코드 | 의미 |
|------|------|
| `rate_degrade` | 성공/수락률 급락 또는 낮은 상태 지속 |
| `attempt_drop` / `attempt_spike` | 시도량 급락/급증 |
| `fail_surge` | 실패·타임아웃 급증 |
| `other` | 기타 운영상 이상 |

라벨은 `data/ib_data/labels/{PLMN}_labels.json`에 저장한다.

### 4.3 Model bias 방지

가능한 경우 초기 human labeling은 특정 모델의 prediction에 종속되지 않도록 수행한다.

모델 overlay는 다음 용도로 사용한다.

- labeling 이후 missed candidate review
- false alarm 분석
- operational calibration feedback 인터페이스

## 5. 모델

### 5.1 Main Backbone — RoCA

메인 backbone은 **RoCA**이다.

사용 이유:

- contaminated training 고려
- unsupervised · multivariate
- continuous anomaly score
- 공개 구현 기반 재현성
- shared model로 확장 가능
- expert calibration과 후단 분리 가능

현재 구현:

- upstream network/loss/augmentation: `RoCA/official/`
- runner: `RoCA/run_plmn.py`
- score: distance-to-center 기반 `loss_n`
- score polarity: **higher = anomaly**
- threshold: train score top-percentile
- prediction export: `data/ib_data/predictions/{PLMN}_roca.json`

RoCA가 모든 TSAD 중 가장 우수하다는 주장은 하지 않는다.

### 5.2 RiAD의 위치

`RiAD/`는 contamination-robust TSAD의 초기 검토 및 pilot comparison용이다.

현재 구현은 원저자 공식 코드가 아닌 **RiAD-inspired practical implementation**이므로:

- Related Work에서 소개
- P0480 pilot 결과는 필요 시 참고/부록
- 메인 backbone 성능 주장에는 사용하지 않음
- RiAD vs RoCA bake-off를 contribution으로 만들지 않음

### 5.3 Preliminary observation

P0480 validation에서:

- RiAD-inspired: VUS-PR 약 0.03
- RoCA: VUS-PR 약 0.076
- RoCA GT event 6개 중 1개 overlap
- 약 43 predicted events 중 대부분 false alarm

해석:

> 본 P0480 individual setting에서 기존 contamination-robust TSAD를 그대로 적용했을 때 operational GT와의 정렬이 충분하지 않았다.

이 결과를 RoCA의 일반적 실패로 확장하지 않는다.

## 6. 연구 1 — Shared Multi-Operator RoCA

### 6.1 Window 구성

서로 다른 사업자의 raw sequence를 직접 concatenate하지 않는다.

사업자 $j$ 내부에서만:

$$
W_{j,t}=[x_{j,t-L+1},\ldots,x_{j,t}]
$$

를 생성한다.

이후 window dataset만 합친다.

```text
Operator 1 windows ┐
Operator 2 windows │
...                ├→ Shared RoCA
Operator 10 windows┘
```

### 6.2 비교

1. **Individual RoCA**
   - 사업자별 독립 모델
2. **Shared RoCA**
   - 10개 사업자 window를 하나의 모델에서 학습

필요 시 normalization variant를 ablation으로 추가한다.

### 6.3 연구 1의 평가

| 역할 | 지표 |
|------|------|
| Primary | **VUS-PR** |
| Event | Event-F1 |
| Additional | PR-AUC, Precision, Recall, F1 |
| Operational reference | FA/day |

사업자별 결과 + Macro Average + Standard Deviation을 함께 보고한다.

Shared의 효과는 사전에 가정하지 않고 **실험으로 검증한다**.

## 7. 연구 2 — Expert Operational Calibration

### 7.1 목표

Shared RoCA가 생성하는 statistical anomaly score를 실제 operational criterion과 맞춘다.

```text
Shared RoCA score
        ↓
Expert feedback + operational context
        ↓
Lightweight calibration
        ↓
Operational anomaly
```

### 7.2 입력 후보

- RoCA score
- traffic volume
- failure count / ratio
- persistence
- baseline deviation
- 관련 counter context

### 7.3 Calibration 후보

- threshold adjustment
- regularized logistic calibration
- 저복잡도 score calibration

소량 label 상황을 고려하여 큰 neural network는 우선 사용하지 않는다.

### 7.4 Feedback budget

$$
0,\ 5,\ 10,\ 20,\ 40
$$

등의 budget으로 valid에서 설계를 확정한 후 test에서 최종 평가한다.

### 7.5 평가

| 지표 | 역할 |
|------|------|
| Event-F1 | event detection |
| Precision / Recall | FP / missed anomaly |
| **FA/day** | operational burden |
| **Detection Delay** | detection speed |
| VUS-PR / PR-AUC | continuous score가 실제로 재정렬되는 경우에만 |

Threshold-only calibration은 score ranking을 바꾸지 않으므로 VUS-PR 개선을 주장하지 않는다.

---

## 8. 평가 프로토콜

### 8.1 지표 정책

- **VUS-PR:** 연구 1 primary
- **Event-F1:** event-level 주요 지표
- **PR-AUC:** threshold-independent 보조
- **Precision / Recall / F1:** threshold 기반 해석
- **FA/day:** operational false alarm burden
- **Detection Delay:** operational timeliness
- **Point-Adjusted F1:** primary에서 제외
- **Accuracy:** 사용하지 않음
- **AUROC:** 필요 시 보조
- **Best-F1 oracle:** 분석 상한으로만 사용

### 8.2 단계별 역할

```text
연구 1 — Shared learning
→ score ranking이 좋아지는가?
→ VUS-PR / PR-AUC / Event-F1

연구 2 — Operational calibration
→ 실제 alert decision이 좋아지는가?
→ Event-F1 / P / R / FA/day / Delay
```

## 9. 논문/보고용 핵심 문장

1. **Train contamination:** 실제 train data에는 normal과 anomaly가 혼재하며, primary experiment에서는 사람 label을 사용한 사전 hard removal을 수행하지 않는다.
2. **Backbone:** 공개 구현을 가진 contamination-robust RoCA를 representative backbone으로 사용하며 SOTA 우위를 주장하지 않는다.
3. **Preliminary:** P0480 individual setting에서 낮은 VUS-PR과 다수 false alarm이 관찰되었으며, 이를 threshold 문제로만 해석하지 않고 후속 연구의 동기로 사용한다.
4. **Shared:** 여러 사업자의 정보를 공유했을 때 individual 대비 anomaly score quality가 달라지는지를 검증한다.
5. **Alignment:** statistical anomaly와 operational anomaly의 불일치를 소량 expert feedback으로 줄이는 lightweight calibration을 평가한다.
6. **평가:** 연구 1은 VUS-PR, 연구 2는 Event-F1·Precision/Recall·FA/day·Detection Delay를 중심으로 평가한다.
7. **범위:** contamination 자체의 신규 해법, backbone SOTA benchmark, unseen operator generalization은 본 연구의 직접 contribution으로 주장하지 않는다.
