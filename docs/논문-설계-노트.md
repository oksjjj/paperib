## 1. 문제 설정

- **도메인:** inbound roaming 제어면 시계열 (5분 샘플).
- **목표 (운용):** 운영상 의미 있는 **품질 이상**(접속 시도·성공/수락률·실패/타임아웃 등)을 탐지하고, 사람(전문가) 라벨과 비교한다.
- **연구 목표:** (1) contamination-robust **RiAD**를 backbone으로 선정(기여 아님), (2) 다수 사업자 **Shared RiAD**, (3) 소량 expert feedback으로 statistical↔operational **calibration** — 상세 [논문-스토리라인.md](./논문-스토리라인.md).
- **비목표:** “통계적으로 평균에서 벗어난 모든 포인트”를 이상으로 두지 않는다. 운용에 무관한 counter 변동은 학습·평가에서 배제한다.

### 1.1 사업자 선정 기준 (논문 10개)

본 연구는 **SKT 인바운드 로밍** 통계를 대상으로 하며, 전체 로밍 사업자 중 아래 기준으로 **10개**를 선정한다.

| 기준 | 내용 |
|------|------|
| 트래픽 규모 | 운용 중요도가 높은 **상위 트래픽** 사업자를 우선 |
| 국가 중복 금지 | 특정 국가 편중 방지 — **동일 국가 사업자 중복 선정 없음** |
| 다양성 | 최종 **서로 다른 10개 국가**의 사업자 |

선정 국가(집합, 사업자 식별과 무관하게 나열):  
중국, 네덜란드, 네팔, 필리핀, 스웨덴, 오스트리아, 베트남, 캄보디아, 미국, 미얀마.

**목적:** 단순히 사업자 수를 늘리는 것이 아니라, volume·일/주 periodicity·variation·baseline·failure 빈도/비율·시간대 패턴 등 **이질적 시계열 특성**을 반영하고, 특정 사업자·국가 패턴에만 종속된 결과를 줄이기 위함이다. (**Shared RiAD** 평가와도 정합.)

**논문 표기·보안**

- PLMN·실제 사업자명은 **공개하지 않는다** (기업 데이터 보호).
- 본문에서는 `Operator 1` … `Operator 10` 등 **익명 식별자**만 쓰고, 필요 시 **국가만** 병기한다.
- git·초안에 masked ID(`P####`) ↔ 원본명·원본 PLMN 대응표를 넣지 않는다.

**논문 기술 예시**

> 본 연구에서는 SKT 인바운드 로밍 사업자 중 트래픽 규모가 큰 사업자를 우선적으로 고려하였다. 특정 국가에 실험 대상이 편중되는 것을 방지하기 위해 동일 국가의 사업자를 중복 선정하지 않았으며, 최종적으로 서로 다른 10개 국가의 사업자를 실험 대상으로 선정하였다. 사업자 식별이 가능한 PLMN 및 실제 사업자명은 기업 데이터 보호를 위해 공개하지 않고 익명화된 식별자를 사용하였다.

**연구 범위의 한계**

- 라벨링·실험 비용상 **전체 사업자가 아닌 10개**로 한정한다.
- 고트래픽 우선 선정으로, 저트래픽 사업자까지 동일 일반화는 **단정하지 않는다**.
- 목적은 전 사업자 일반화가 아니라,  
  **“서로 다른 국가·트래픽 특성을 가진 주요 로밍 사업자에 대해 제안 TSAD의 적용 가능성을 검증”** 하는 것으로 한정한다.

## 2. 데이터 · 분할

| 항목 | 설계 |
|------|------|
| 샘플 간격 | **5분** |
| 분할 | 시간 순 **train 60% / valid 20% / test 20%** (기본) |
| scaler | train만 fit (MinMax 등), valid/test는 transform |
| 사람 라벨 ∩ train | RiAD 등 robust backbone은 contamination을 전제로 할 수 있음. 기존 `drop_labeled_from_train`(hard drop)은 **선택적 비교·레거시**로 유지. |
| valid | 임계값·F1·라벨링 UI · expert feedback / operational calibration |
| test | **held-out**. 튜닝을 보며 맞추지 않음. 최종 보고용 |

라벨링 UI에는 TRAIN / VALID / TEST 밴드를 표시한다. 드롭다운은 **논문 PLMN 10개만** 노출.

## 3. Feature 뷰 (run)

세 가지 run을 분리해 산출물(체크포인트·예측 JSON)이 서로 덮어쓰지 않게 한다.

| run | 입력 | 표준화 | 역할 |
|-----|------|--------|------|
| **`paperib`** | 전체 raw counter | MinMax (train fit) | full multivariate baseline |
| **`comb`** | 품질 관련 raw 14개 + SUCCESS/ACCEPT rate | MinMax | 운용 해석 가능한 소수 feature |
| **`comb_share`** | M971 + (나머지 counter ÷ M971) | M971: log1p→MinMax; share: MinMax | 시도량 대비 **비율** 중심 |

metric별 사전 제외(예: 과거 M688 drop)는 두지 않는다. 희소·오염 feature는 contamination-robust backbone(RiAD) 가정과 정합.

`window_length` ≠ 100이면 경로에 `_w{N}`을 붙여 기본 win=100 산출물과 분리한다.

## 4. 사람 라벨 (GT)

### 4.1 정의 원칙

- 라벨은 모델 출력이 아니라 **운영·연구상 이상으로 합의한 구간**.
- **SUCCESS/ACCEPT rate는 스크리닝 렌즈**이지, 라벨의 유일한 정의가 아니다.  
  rate만으로 자동 GT를 만들면 multivariate 평가가 “성공률 급락 탐지”로 붕괴한다.
- **성공률·수락률이 일시적으로만 비정상적으로 올라갔다가 회복**하는 구간은 이상으로 두지 않는다 (“좋은 쪽 이탈”).
- 확정 전 FAIL/TO 등 **동반 신호**를 확인한다. rate는 애매한데 실패 계열만 튀는 구간도 valid/test에 일부 포함한다.

### 4.2 형식 · 판정 기준

- **구간(range) 우선**, 점은 순간 이벤트만.
- 저장: `data/ib_data/labels/{PLMN}_labels.json`
- 라벨마다 판정 기준(`reasons`, 복수 가능) + 선택적 메모:

| 코드 | 의미 |
|------|------|
| `rate_degrade` | SUCCESS/ACCEPT rate 급락 및/또는 낮은 지속 |
| `attempt_drop` / `attempt_spike` | M971 급락 / 급증 |
| `fail_surge` | 실패·타임아웃 폭증 → `fail_metrics`에 해당 지표(복수) |
| `other` | 기타 (메모 권장) |

- ~~`multi_collapse`~~ 는 사용하지 않음 (rate / attempt / fail로 충분).

세부·예시: [라벨링-원칙.md](./라벨링-원칙.md).

### 4.3 라벨링 UI (요지)

- rate 패널 + raw counter, 드래그 줌 시 Y 자동.
- 사람 라벨(금) / 모델 예측(보라) 오버레이, 기여 metric.
- 판정 기준 체크 · fail 지표 멀티선택 · 메모 (전환·Save 시 반영).
- 구간 편집: 경계선 드래그, **5분 스냅**.

## 5. 모델 · 점수 · 임계값

### 5.1 OmniAnomaly

- 비지도 VAE + planar NF 등 (벤더 코드 기반).
- 점수: reconstruction log-prob 계열 → **낮을수록 이상** (`score < threshold`).
- valid에서 POT (및 필요 시 best-F1)로 임계값·구간 export. **Primary 비교는 POT(label-free)**; best-F1은 oracle 상한.
- train 사람 라벨 구간은 학습에서 제외.
- **관찰·논문 시사점 (mild 복원 / severe 편중 / baseline 실익):** [OmniAnomaly-관찰.md](./OmniAnomaly-관찰.md).

### 5.2 Anomaly Transformer

- Association discrepancy 기반 (ICLR’22).
- UI 호환을 위해 **stored_score = −energy** (높을수록 정상; `score < 0` ≈ energy threshold).
- Omni와 동일 분할·run_name(`paperib` / `comb` / `comb_share`).

### 5.3 평가 역할 분리

| 구간 | 사용 |
|------|------|
| Train | RiAD 학습 · primary thr (percentile) |
| Valid | 지표·UI · HP / calibration 튜닝 |
| Test | 최종 held-out (튜닝 후 1회) |

### 5.4 논문 지표 (2026-11-03)

| 역할 | 지표 |
|------|------|
| Primary | **VUS-PR** |
| Event | Event-F1 |
| Additional | PR-AUC, P/R/F1 |
| Operational | FA/day, Detection Delay |
| 제외 | Point-Adjusted F1, Accuracy (AUROC는 보조만) |

연구 1: 사업자별 + Macro Average + Std.  
상세: [논문-스토리라인.md](./논문-스토리라인.md) §5–6.

## 6. 논문/보고에 명시할 문장 (초안)

1. **GT:** 운영상 품질 이상. rate로 후보를 찾고 FAIL/TO·시도량 등으로 확인하며, rate 단독 임계값으로 GT를 만들지 않았다.  
2. **성공률 급등:** 일시적 상승 후 회복은 이상으로 라벨하지 않았다.  
3. **분할:** chronological 60/20/20. 사람 라벨이 있는 train 구간은 비지도 학습에서 제외.  
4. **Feature:** (a) full raw (`paperib`), (b) COMB raw+rates, (c) COMB share(÷M971). metric 사전 제외 없음.  
5. **평가:** Primary **VUS-PR**; Event-F1; PR-AUC·P/R/F1; FA/day·Detection Delay. PA-F1·Accuracy 비주용. thr는 label-free(train percentile).  
6. **스토리라인:** RiAD → Shared multi-operator → expert operational calibration — [논문-스토리라인.md](./논문-스토리라인.md).  
7. **사업자 선정:** 고트래픽 우선 · 국가 비중복 · 10개국 / Operator 익명 (§1.1).
